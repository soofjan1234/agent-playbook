# 验证与收尾

用当前证据完成工作，并让分支和上下文都有明确去向。

<HARD-GATE>
没有当前回合的新鲜验证证据，不得声称完成、修复、构建成功或测试通过。
</HARD-GATE>

## 按变更类型选择验证

验证强度应与变更风险和实际影响匹配。

- 仅修改说明性 Markdown、注释或交接文档，且不影响代码、配置、生成物或接口契约时，不运行无关的代码测试、构建或部署验收；检查实际差异、内容完整性、状态一致性和相关链接即可。
- 文档同时定义配置、接口契约、生成流程或可执行命令时，验证受影响的契约或命令。
- 当前回合的新鲜验证证据不等同于必须执行测试；文档检查、差异检查和契约核对也可以构成相应结论的证据。

## 验证关卡

1. 为每项结论确定能证明它的命令或检查。
2. 运行完整且相关的验证，读取退出码、失败数和关键输出。
3. 失败时报告实际失败，不用“基本完成”弱化结果。
4. 成功时同时说明执行了什么和证据是什么。
5. 若当前工作项已登记状态账本：全部必需验证通过后更新为 `已完成`；当前环境可运行的自动验证通过但仍缺外部或人工验证时更新为 `待验证`；验证失败或实现未就绪时保持或退回 `待实现`。具体规则见 [状态账本规范](../references/status-ledger.md)。

| 结论 | 必需证据 |
| --- | --- |
| 测试通过 | 测试命令退出码为 0，且确认无失败 |
| 构建成功 | 构建命令退出码为 0 |
| Bug 已修复 | 原始症状或回归测试通过 |
| 需求完成 | 逐项核对需求与变更 |
| agent 已完成 | 独立检查实际差异和输出 |


## 分支收尾

验证通过后，根据实际 Git/worktree 状态提供固定选择：

1. 本地合并。
2. 推送并创建 PR。
3. 保持现状供后续处理。
4. 丢弃工作。

丢弃前要求用户输入明确确认；只清理由当前流程创建且确认安全的 worktree。创建 PR 后保留工作区以便继续审查。

## 会话移交

需要新会话继续时，生成精简移交文档，包含目标、当前状态、未完成事项、验证证据和建议调用的 skill。已有规格、计划、ADR、Issue、提交和差异只引用路径或链接，不重复复制。

创建或更新交接文档时，必须按 [状态账本规范](../references/status-ledger.md) 创建或更新记录中的主要文档、真实状态、下一步和最后更新日期。没有设计或计划记录时由交接文档首次创建记录；仍需实现或自动验证时使用 `待实现`，只缺外部或人工验证时使用 `待验证`，不因生成交接文档而标记 `已完成`。

## 红旗

- 引用旧测试结果作为当前完成证据。
- 用 lint 结果代替构建或测试结果。
- 未经确认删除分支、worktree 或用户工作。
- 移交文档复制大量已经存在的内容。
