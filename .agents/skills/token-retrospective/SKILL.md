# Token 复盘

## 目标

从一次高成本回合里识别可避免的浪费，判断是否存在值得保留的经验。除非证据不足，否则不要重新运行大范围搜索。

## 检查清单

1. **说清触发原因：** 是什么让这轮变长？例如：目标文件不明确、缺少本地 fixture、看错来源、重复验证、搜索过宽、工具失败、沙箱/网络提权、或假设过时。
2. **区分必要与浪费：** 保留真正改变答案的工作；标出只是为了弥补可避免含糊而产生的工作。
3. **找出最早的更省分支：** 找到第一个本可以通过文件检查、一个澄清问题、更窄命令或本地 fixture 来缩短路径的时刻。
4. **判断是否需要规则：** 只有原因会复发、能改变后续决策且现有规则没有覆盖时，才提出持久指令；偶发失败可以得出“无需新增规则”。区分已观察事实与推断，项目经验放项目范围，普适习惯才考虑全局，可复用流程才考虑 skill。
5. **保持规则很小：** 候选只写一句话或短 bullet，不复制复盘叙事；真正写入 `AGENTS.md` 或 skill 前，遵循现有设计确认要求。

## 输出格式

```text
为什么耗时：
- ...

下次更省：
- ...

是否需要新增规则及依据：
- ...（可以是无需新增）

候选及适用范围（仅有必要时）：
- ...
```

## 常见值得加入的规则

- 在进行网络或远程调试前，先检查已有本地 fixture 是否能证明当前问题；符合当前验证目标时直接使用，只有会改变验证含义或范围的取舍才询问。
- 复盘失败时，先打印数量和第一个差异位置，而不是直接倾倒巨大值。
- 面对宽泛问题时，先给一个紧凑的默认回答，再询问是否需要检查本地文件。
- 不要把终端乱码复制进源文件；使用明确 UTF-8 读取，或用稳定锚点定位。
