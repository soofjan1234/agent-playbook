# 按需设计检查

仅在任务涉及相应技术问题时使用。检查用于发现遗漏，正文只保留影响本次决定、实现或验收的内容，不要求逐项建立章节。

## 技术问题

- **组件与流程**：谁负责什么、依赖谁、请求或数据怎样流转；模块和资源的所有权是否明确。
- **数据与持久化**：数据关系、约束、事务、幂等、版本、迁移和回滚；失败后哪些内容必须保持一致。
- **状态与恢复**：状态转换、超时、取消、重试、断连和重启；何时可以继续、何时必须保留未决状态，以及谁负责恢复。
- **接口与兼容**：请求、响应、消息和错误语义；身份、权限、并发限制，以及旧调用方如何受影响。
- **运行与观测**：配置、依赖、资源限制、部署和故障诊断；用户或运维怎样判断成功、等待或失败。

## 方案与验证

- 有实质取舍时，比较候选的收益、代价和适用条件，给出推荐；约束已经排除其他方案时说明关键理由即可。
- 技术判断先用当前实现或可靠资料核对；需要实验时先明确候选、条件、资源限制和成功标准。
- 为关键风险给出能区分正确与错误行为的验证方法，覆盖相关失败路径；区分本地测试、集成验证与目标环境验收。
- 发现目标、范围或验收不可行时，只重新讨论受影响部分；实现步骤仍留给 plan-work。
