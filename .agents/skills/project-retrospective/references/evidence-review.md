# 复盘证据审查规范

本规范用于 `project-retrospective` 的三类独立只读审查。目标是获得互补证据，不是生成三份面向用户的最终报告。

## 共享输入契约

主 Agent 在委派前冻结本轮任务包，只提供当前角色需要的内容：

- 从触发本任务的用户请求到完成或阻塞结论，不默认包含整个长期线程。
- 原始目标、范围、非目标以及用户明确批准和纠正。
- 适用的仓库规范、授权边界和禁止操作。
- 可定位的仓库、基准点、目标点、产物路径和已有验证证据；不存在的字段明确标记为无。

缺少基准或产物位置时，主 Agent 先精确定位或把限制写入任务，不让 subAgent 宽泛搜索。各 subAgent 不读取其他审查者的结论，避免相互污染。

## 共享执行边界

- 只读调查，不修改文件、配置、分支、远程状态或外部系统。
- 不继续委派 subAgent，不扩大到任务生命周期之外。
- 区分已验证事实、合理推断和待确认事项。
- 每条发现包含严重度、类别、证据位置、影响、建议和验证方式。
- 没有发现时明确说明，并列出未覆盖证据和残余风险。
- 无法取得必要证据时停止对应判断，不用会话中的完成声明代替真实事实。

## Agent 自身操作审查

只审查执行过程，不判断代码或设计产物本身是否正确。

输入重点：原始请求、任务时间线、用户批准与纠正、工具调用和失败、验证结果、最终声明。

输出证据备忘录：

1. 关键决策和操作时间线。
2. 必要工作与可避免成本。
3. 最早可以采用的更短路径。
4. 遗漏或违反的范围、授权、验证和沟通关卡。
5. 完成声明与当前证据是否一致。
6. 最多三条可持久化候选规则；不决定写入位置。

## 设计、计划审查

只审查设计和计划产物，不评价 Agent 的对话表现，也不检查代码实现质量。使用 `review-work` 的 [设计评审](../../review-work/references/design-review.md) 和 [计划评审](../../review-work/references/plan-review.md)；只有一种产物时只读取对应 reference。

输入重点：原始目标、批准版本、设计或计划路径、相关当前事实和验证约束。

输出按设计、计划分区：

- 设计：错误、遗漏、可简化项、可优化项和未决风险。
- 计划：设计追溯、范围一致性、纵向切片、依赖顺序、执行精度、验证闭环和可交接性。
- 设计未成立时，将其列为上游问题，不用计划细节抵消。

## Code Review

只审查真实代码差异，不评价 Agent 对话表现，也不重新设计未批准方案。使用 `review-work` 的 [代码变更评审](../../review-work/references/code-review.md)。

输入重点：原始需求、已批准设计或计划、仓库路径、基准与目标、真实 diff、未跟踪文件和已有测试证据。

输出证据备忘录：

- 按阻断、重要、建议列出需求、正确性、规范、设计、测试和规模问题。
- 每项定位到最窄文件、行号或符号，并说明复现或验证方式。
- 质量工具、文件行数和测试只作为证据，不能单独证明缺陷。
- 环境无法覆盖的测试、race、构建或运行行为作为残余风险报告。

## 主 Agent 汇总关卡

1. 回到原始请求和一手证据核对所有发现。
2. 合并重复发现，拒绝无证据、越界或互相矛盾的结论。
3. 将操作原因与设计、计划影响和代码后果关联；没有证据时不强行建立因果。
4. 区分本轮缺陷、可避免成本、仍需验证事项和持久化候选。
5. 只生成一份项目复盘与最小沉淀提案；用户批准前不实施修改。
